# 关键路径验收契约

`critical-paths.json` 是浏览器验收与标准发行证据校验共用的权威清单，schema_version=1。2026-10-18体验增补保留原11场景/48断言/19视口组合，新增CP12加载缓存、CP13图表操作、CP14业务状态与诊断隔离；现为14场景/65断言/25视口组合，原42加新增24，共66个截图槽位。合同不保存账号、令牌、实际用户数据或执行结果。

发行接线见 [同包验收门禁](../../docs/public/release-acceptance.md)。执行器读取 `required_scenarios`，按场景所需视口执行每条断言；验证器拒绝缺场景、缺断言、缺视口/截图、skip及非PASS。证据应绑定此文件实际SHA-256和被验收发行包，不把一份旧报告复用到新包。

正常路径必须在真实Django与编译页面运行。已有 `data-chart=quota-gauge`、`transfer-composition`、`usage-timeseries` 是图形定位入口；它们只被源码包含不算通过。至少一条会话从登录沿可见导航走完整路径。

新增场景均验桌面与390px。首次7d/月/年分别保留请求开始、等待与完成的证据；缓存往返/离页返回须在新响应前验证，失败/迟到/撤权和日月年/重置边界不能只看最终成功截图。hover/focus/touch须实际操作并拍清楚数值卡，触屏不能由click代替；普通用户API隔离和管理员同服务诊断入口都需验证。完整断言、检查点及边界时钟限制见[机器合同](critical-paths.json)。

执行器沿用既有证据格式，不能自动补PASS；过程截图允许保留局部loading或活动提示卡，但不放宽旧截图容差或隐藏关键值。边界时间推进只验证隔离行为，不声称真实账期或C0通过。新截图差异必须关联本批需求并独立审阅，自动更新基线不构成验收。

本批另获准静态兼容上限2→3，现行要求位于`execution_contract.static_compatibility_rule`及`static_compatibility_evidence`：保持7天上界、既有原截止、固定摘要及当前损坏不fallback；前批2项报告仍为历史。主代理须关联同源码后端兼容测试的实际结果，明确这是辅助后端验证；当前发行验证器未自动消费该结果，不得冒称CP11浏览器已验证扩容，原CP11仍必验。

修改场景/断言需关联现行需求、同步当前Implementation Plan并通知所有消费者；不得为了消除失败自动删断言、跳过、放宽容差或更新截图。`undelivered_scope` 记录本批不能宣称完成的长期要求，不是可以忽略的需求，也不是本批假PASS占位。
