# 原订阅与套餐的显式关联

本功能是本地候选实现，不表示生产已经迁入套餐计量。它解决原P8交付和已有套餐同时存在时的服务重复、编号变化及兼容解析问题，不创建或应用套餐额度。

## 行为

- 一个P8来源只关联一个既有Entitlement，目标也只能关联一个P8来源。目标必须与原P8属于同一用户、使用相同public ID，旧会员编号继续作为别名。
- 列表、本人详情、用量和管理员视图仍显示一份服务；下载继续使用原P8资源与稳定地址，软件选择不生成第二份套餐。
- 摘要与账本从目标套餐读取；尚未应用的配置不伪装为已生效，未取得个人计量时不补零或使用机器统计。
- 预览不写入；确认只建立经过核验的关联，不改额度、历史、账期、到期或凭据。相同首次请求可原样重放，不增加修订或写记录。
- 用户、来源、会员修订或目标发生冲突时关闭该映射。异常快照不会使其他用户请求报错；错误引用他人的合法套餐不会隐藏它。
- 失效映射不能绕过页面直接调用账期API。取消关联也不代表旧下载链接或核心连接已撤销。

## 本地预览

完成0018迁移并准备隔离数据库中的已有用户、P8和目标套餐后，可运行管理命令p8_entitlement_preview。必填参数是--actor-id、--p8-service-id、--entitlement-id；--expected-revision默认0。

命令只输出关联编号、修订与保留项，没有apply选项，在PANEL_LIVE模式拒绝运行。操作人必须是当前有效管理员。未知编号、不同用户、编号冲突或过时修订都会拒绝预览。

程序接口在portal.p8_entitlement中：preview_p8_entitlement、verify_p8_entitlement、revoke_p8_entitlement。确认与撤销只允许非生产环境；原有生产读取兼容不因此关闭。发布到生产需要独立的真实归属与变更清单，不能把测试参数用于现场。

0018只有新映射表，没有数据迁移；不自动为已有账号建立套餐、赋值额度、开始新账期或轮换链接。代码回滚也不等于数据回滚，已填充映射后的现场回退必须单独验证。

## 当前边界

此关联不启用核心计数或套餐硬限制。每授权项倍率、持久采样区间、自然日/月统计、用户仪表盘纠偏与统计标头仍由后续工作接入。旧P8下载凭据的失效处理和完整核心撤销能力没有通过全部验收。

验证可运行tests.test_p8_entitlement_binding、tests.test_p8_billing_guard和tests.test_p8_entitlement_preview_command，均使用假数据。完整公开回归入口为scripts/public/test_panel.py，现场依赖另行列出。
